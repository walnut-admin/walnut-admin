# Walnut Admin 全容器化部署实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将前端、后端、Nginx 全部容器化，用 GitHub Actions 构建镜像推到腾讯云 TCR，服务器上单一 docker-compose 部署，替换现有的 PM2 + 宿主机 Nginx 方案。

**Tech Stack:** Docker / docker-compose / GitHub Actions / pnpm workspace / Vite / NestJS / nginx / brotli / 腾讯云 TCR（ccr.ccs.tencentyun.com）

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    # history 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 预压缩 .br 文件（构建时 vite-plugin-compression2 生成）
    brotli_static on;
    brotli on;
    brotli_comp_level 6;
    brotli_min_length 20;
    brotli_types text/plain text/css application/json application/x-javascript text/xml application/xml application/xml+rss text/javascript application/javascript image/svg+xml;

    gzip on;
    gzip_vary on;
    gzip_comp_level 6;
    gzip_min_length 10240;
    gzip_types text/plain text/css text/javascript application/javascript application/json application/xml image/svg+xml;

    # 静态资源强缓存（文件名带 hash）
    location /static/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

> 注意：`brotli_static` 需要 brotli 模块——前端镜像将使用 Task 4 的 brotli 镜像，而非官方 nginx:alpine。若构建报错 "unknown directive brotli_static"，说明镜像未包含模块，回到 Task 4 检查模块安装。

### Task 4: nginx brotli 入口镜像

**Files:**
- Create: `deploy/nginx/Dockerfile`

关键事实：
- nginx:alpine 官方镜像是 `apk add nginx` 安装（与 Alpine 仓库同源），因此 `apk add nginx-mod-http-brotli` 版本天然匹配（同 repo 同版本线）
- brotli 动态模块路径：`/usr/lib/nginx/modules/ngx_http_brotli_filter_module.so` 与 `ngx_http_brotli_static_module.so`
- `load_module` 指令必须出现在 http 块之前；官方 nginx:alpine 的 nginx.conf 是否 include `/etc/nginx/modules/*.conf` 需构建期验证（Step 3 兜底）

- [ ] **Step 1: 创建 Dockerfile**

```dockerfile
FROM nginx:1.27-alpine

# Alpine 官方仓库提供 brotli 动态模块（与镜像内 nginx 同源同版本线）
RUN apk add --no-cache nginx-mod-http-brotli

# load_module 必须置于 http 块之前；官方 nginx.conf 若未 include modules 目录，
# 则覆盖 nginx.conf（见 Step 3 备选）
RUN printf 'load_module /usr/lib/nginx/modules/ngx_http_brotli_filter_module.so;\nload_module /usr/lib/nginx/modules/ngx_http_brotli_static_module.so;\n' > /etc/nginx/modules-brotli.conf \
    && sed -i '1a include /etc/nginx/modules-brotli.conf;' /etc/nginx/nginx.conf

# 构建期验证：模块加载失败（版本不匹配）→ 构建失败
RUN nginx -t
```

> `sed -i '1a ...'` 在第一行（`user nginx;` 或注释）后插入 include——若 `nginx -t` 报错（如 "unexpected end of file" 或指令位置错），备选方案：把两行 `load_module` 直接写入 `/etc/nginx/nginx.conf` 顶部（`sed -i '1i ...'`）再 `nginx -t`。

- [ ] **Step 1: 重写 workflow**

创建（覆盖）`.github/workflows/deploy.yml`：

```yaml
name: Deploy Docker Images to Server

on:
  workflow_dispatch:
    inputs:
      environment:
        description: Environment to deploy
        required: true
        type: choice
        options:
          - prod

env:
  REGISTRY: ccr.ccs.tencentyun.com
  IMAGE_NS: walnut-admin
  TAG: ${{ github.sha }}

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 11

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      # 前端构建输入：.env.keys 解密 env-encrypted → env-local
      - name: Prepare env (.env.keys → setup-env)
        run: |
          echo "${{ secrets.ENV_KEYS }}" > .env.keys
          pnpm setup-env
        # 注意：secrets 会被 Actions 自动打码，日志安全

      - name: Login to Tencent TCR
        run: echo "${{ secrets.TCR_PASSWORD }}" | docker login $REGISTRY -u "${{ secrets.TCR_USERNAME }}" --password-stdin

      - name: Build & push backend
        run: |
          docker build -f apps/server/Dockerfile -t $REGISTRY/$IMAGE_NS/backend:$TAG .
          docker push $REGISTRY/$IMAGE_NS/backend:$TAG

      - name: Build & push frontend
        run: |
          docker build -f apps/admin/Dockerfile -t $REGISTRY/$IMAGE_NS/frontend:$TAG .
          docker push $REGISTRY/$IMAGE_NS/frontend:$TAG

      - name: Build & push nginx
        run: |
          docker build -f deploy/nginx/Dockerfile -t $REGISTRY/$IMAGE_NS/nginx:$TAG .
          docker push $REGISTRY/$IMAGE_NS/nginx:$TAG

      - name: Deploy on server
        uses: appleboy/ssh-action@v0.1.10
        with:
          host: ${{ secrets.PROD_HOST }}
          username: ${{ secrets.PROD_USERNAME }}
          password: ${{ secrets.PROD_PASSWORD }}
          script: |
            cd /opt/walnut-admin/deploy
            # 只替换 IMG_TAG 行，保留服务器上的人工配置（数据层密码等）
            if [ -f .env ] && grep -q '^IMG_TAG=' .env; then
              sed -i "s/^IMG_TAG=.*/IMG_TAG=${{ env.TAG }}/" .env
            else
              echo "IMG_TAG=${{ env.TAG }}" >> .env
            fi
            docker compose pull
            docker compose up -d
            docker image prune -f --filter "until=72h"
```

> 说明：
> - 部署目录固定为服务器 `/opt/walnut-admin/deploy`（Task 7 初始化；如需沿用现网目录，实现时调整）
> - 服务器 `deploy/.env` 首行为 `IMG_TAG=`，其余行（MONGODB_*、REDIS_PASSWORD）由人工维护，CI 只更新 IMG_TAG 行
> - 若需要 `push main` 自动触发，追加：
>   ```yaml
>   push:
>     branches: [main]
>   ```
>   默认保持手动触发（与现网 release 流程一致）

| nginx brotli 模块版本不匹配 | Dockerfile 构建期 `nginx -t` fail fast；备选方案见 Task 4 |
